# Architecture

Silly Starter is a small Next.js application with a single page and a set of
pure TypeScript utility modules. The page is a demonstration surface. The
libraries under `src/lib` are the reusable part of the repository: numeric,
string, array, object, date, and async helpers that do not depend on React.

## Repository layout

```
starter-repo/
  src/app/            App Router entry, global styles, the home page
  src/components/     Presentational React components used by the page
  src/lib/            Framework-free utility modules and Vitest tests
  public/             Static files served from the site root
  docs/               Project documentation, including this file
```

`src/app/layout.tsx` defines the root HTML document, metadata, and the import
of `globals.css`. `src/app/page.tsx` is the only route. It composes four
components and does not fetch data or read request state. `src/app/globals.css`
loads Tailwind and a few animation utilities used by the floating background.

`public/` holds assets that Next serves as-is. Nothing in the current page
references those files; they are available for later routes.

## Build and language setup

The app runs on Next.js 16 with the App Router, React 19, and TypeScript 5.
`package.json` exposes four scripts:

- `npm run dev` starts the Next development server.
- `npm run build` produces a production bundle.
- `npm run start` serves that bundle.
- `npm run lint` runs ESLint with the Next flat config in `eslint.config.mjs`.

`next.config.ts` keeps the Next configuration in TypeScript. The PostCSS
config enables Tailwind CSS v4 through `@tailwindcss/postcss`. Tailwind is
imported from `globals.css` with `@import "tailwindcss"`; there is no
`tailwind.config` file because v4 reads theme information from CSS.

`tsconfig.json` turns on strict checking, leaves emit to Next (`noEmit`), and
resolves modules with `bundler`. The `@/*` path alias maps to `./src/*`, which
is how the page imports `@/components/Hero` and how tests can import sibling
modules with relative paths. `next-env.d.ts` is generated by Next and should
not be edited by hand.

## Runtime shape

The home page is a server component. It renders a full-viewport gradient, a
decorative layer of floating emoji, and a centered column:

1. `Hero` — eyebrow, title, and tagline.
2. `DuckButton` — a client component. The `"use client"` directive is local
   to that file because the button stores the latest quip in React state.
3. `SillyFacts` — a server component that lists static copy.
4. `FeatureGrid` — six static cards (runtime, styling, types, routing, the
   duck, and npm scripts).

Client state does not cross the server boundary. The duck's quips live inside
`DuckButton`, and the rest of the page is static markup. Dark mode follows the
user's `prefers-color-scheme` through Tailwind's `dark:` variants.

## Utility modules

Each file in `src/lib` exports plain functions. They do not import Next, React,
or Node-only APIs except for timers in `async.ts`. Invalid numeric domains
throw `RangeError` before any work is done. Inputs are not mutated.

### `math.ts`

Thirty numeric helpers. Interval operations (`clamp`, `clamp01`, `lerp`,
`inverseLerp`, `remap`, `smoothstep`) sit next to integer theory (`gcd`,
`lcm`, `isPrime`, `nextPrime`, `factorial`, `fibonacci`) and summary
statistics (`sum`, `mean`, `median`, `variance`, `product`). Geometry helpers
(`hypot`, `distance`, `degToRad`, `radToDeg`) and rounding helpers
(`roundTo`, `snap`, `mod`, `approximatelyEqual`) cover the remaining cases.
`factorial` stops at `20` and `fibonacci` stops at `78` so results stay inside
the safe integer range. `isPerfectSquare` rejects values outside that range
because `Math.sqrt` cannot distinguish nearby integers there.

### `strings.ts`

Twenty-five string helpers. Case conversion (`capitalize`, `uncapitalize`,
`camelCase`, `kebabCase`, `snakeCase`, `titleCase`, `swapCase`) shares one
word splitter so "hello world" and "helloWorld" produce the same tokens.
Search and slicing helpers (`truncate`, `countOccurrences`, `between`,
`removePrefix`, `removeSuffix`, `mask`) treat empty needles as errors.
`slugify` strips diacritics before replacing non-alphanumerics. `interpolate`
replaces `{key}` tokens and leaves unknown keys in place.

### `arrays.ts`

Twenty-five array helpers. Set-style operations (`unique`, `intersection`,
`difference`, `union`, `uniqBy`) preserve the order of the first list.
Windowing helpers (`chunk`, `windows`, `take`, `drop`, `takeWhile`,
`dropWhile`, `rotate`) copy slices rather than splicing the input. `groupBy`,
`keyBy`, and `frequencies` return `Map` so keys are not coerced to strings.
`sortBy` is stable for equal keys. `minBy` returns `undefined` for an empty
list and rejects a non-finite projection.

### `objects.ts`

Twenty-five object helpers aimed at plain objects. `pick` and `omit` copy own
keys only, so inherited properties never leak into the result. `getPath`,
`setPath`, and `hasPath` walk dotted paths and accept array indexes.
`deepMerge` clones nested objects and arrays from the source so later mutation
of the result cannot touch the input. `deepEquals` compares plain objects,
arrays, and primitives with `Object.is` for the leaf case, which treats `NaN`
as equal to itself. `diffKeys` reports keys whose deep values differ,
including keys present on only one side.

### `dates.ts`

Twenty date helpers, all in UTC. `addMonths` clamps the day to the length of
the destination month, so 31 January plus one month lands on the last day of
February. Years 0 through 99 are written with `setUTCFullYear` because
`Date.UTC` otherwise maps those years onto 1900–1999. `parseISODate` accepts
only `YYYY-MM-DD` and checks the day against the real length of the month.
`formatRelative` uses `Intl.RelativeTimeFormat` and picks the largest unit
that fits the elapsed time.

### `async.ts`

Twenty asynchronous helpers. `retry` uses `backoffDelay` between failures and
rethrows the last error. `debounce` waits for a quiet period; `throttle`
runs on the leading edge and schedules one trailing call. `withTimeout` races
a timer and always clears it when the source promise settles. `mapLimit` and
`createQueue` cap how many tasks run at once. `createMutex` serializes
critical sections. `once`, `singleflight`, and `memoizeAsync` share in-flight
work; only successful results are cached, so a rejection can be retried.
`poll` stops on the first non-nullish value. `tryAsync` and `settle` convert
rejection into data. `firstFulfilled` resolves with the earliest success.

## Testing strategy

Each module has a sibling `*.test.ts` file written for Vitest. Every exported
function has a case that checks the documented example and, where the domain
is narrow, a case that expects `RangeError`. Tests import the module under
test by relative path and do not boot Next.

The suite is intentionally local:

- Pure functions are asserted with `toBe` or `toEqual`.
- Date tests construct instants with a `Z` suffix and compare `toISOString`
  output, so the host timezone cannot change the result.
- Async tests use short real timers (`sleep` of a few milliseconds) instead
  of fake timers, which keeps debounce, throttle, mutex ordering, and
  singleflight easy to read.

Vitest 3 is a dev dependency. Run `npx vitest run` from the repository root.
The tests are included by `tsconfig.json`, so those types are part of
`tsc --noEmit`. `npm run lint` covers the Next app and the new modules through
the existing flat config.

## What lives where

Add a route by creating a folder under `src/app`. Add a visual piece used by a
route under `src/components`, and mark it `"use client"` only when it needs
state or browser events. Add a reusable calculation to the matching file in
`src/lib`, export it, give it a JSDoc example, and add a test next to the
module. Keep those modules free of React so they can be imported from server
components, client components, and tests without pulling in a rendering tree.
